# OpenPath — Desktop Shell (Tauri 2)

A native window around the unchanged Fastify server. The server is bundled
into a single CJS file and run by a **renamed Node runtime** as a Tauri
*sidecar*; the Tauri window then loads `http://127.0.0.1:<port>/` — the same
HTML the browser would have gotten. One window, one SQLite file, no rewrite.

```
┌──────────────────────────── Tauri app ────────────────────────────┐
│  WebView ──loads──> http://127.0.0.1:<free-port>/                 │
│                        │                                          │
│                        ▼                                          │
│  sidecar: server-<triple>[.exe]  (= the Node runtime, renamed)    │
│           └── openpath/server/app.cjs  (esbuild bundle, 3.5 MB)   │
│                 ├── better-sqlite3/  (runtime subset, ~2 MB)      │
│                 └── ../../dist/web  (built SPA, ~1.2 MB)          │
│                        │                                          │
│                        ▼                                          │
│              <app-data-dir>/openpath.db                           │
└───────────────────────────────────────────────────────────────────┘
```

## Why this architecture

| Decision | Why |
| --- | --- |
| Node sidecar, not `node --build-sea` (SEA) | SEA is blocked by the Tauri notarization bug [tauri#11992](https://github.com/tauri-apps/tauri/issues/11992) — the postject Mach-O surgery corrupts the macOS bundle. A renamed runtime is the same ~87 MB payload with zero surgery. |
| Node, not Bun | Bun's incomplete N-API ([oven-sh/bun#19578](https://github.com/oven-sh/bun/issues/19578)) can break `better-sqlite3`. |
| Node, not `pkg` | pkg is unmaintained and its filesystem-patching approach is fragile. |
| Node, not a pure-Rust rewrite (rusqlite) | It would throw away the Fastify server, all migrations, and the API — a rewrite, not a port. Revisit only if download size ever beats feature parity. |
| better-sqlite3 via N-API prebuild | v13 ships `prebuilds/<platform>-<arch>.node` (~2 MB) that is **ABI-stable across Node versions**, so any runtime works — CI pins the current release line (Node 26), and `pnpm check-updates` + `version-check.yml` flag when to move it. |
| `openpath/server/` nesting of the bundle | `server/index.ts` resolves the built SPA as `path.join(__dirname, '..', '..', 'dist', 'web')`. Nesting the bundle two levels under the dir that holds `dist/web` (`app/openpath/server/app.cjs` + `app/dist/web/`) makes that resolve correctly **with zero server changes**. |

## Layout

| Path | What |
| --- | --- |
| `src/main.rs` | Thin bin → `openpath_lib::run()` |
| `src/lib.rs` | Sidecar lifecycle: free port, env wiring, health-gated window, kill on exit |
| `tauri.conf.json` | `frontendDist: ../dist/web`, `externalBin: ["binaries/server"]`, `resources: ["app/**/*"]`, targets `deb / appimage / dmg / nsis` |
| `capabilities/default.json` | `shell:execute` permission for the `server` sidecar |
| `icons/` | Generated by `scripts/make-icons.mjs` |
| `native/` | Sidecar payload (gitignored, rebuilt by `pnpm sidecar` / CI) |
| `binaries/` | Renamed Node runtime(s) (gitignored) |

## Local development

```bash
# 1. one-time: install desktop deps (@tauri-apps/cli + Rust toolchain)
pnpm install
# 2. build the sidecar payload for this machine
pnpm sidecar
# 3. run the desktop app (starts the Vite dev server + Tauri window)
pnpm tauri:dev
```

`pnpm tauri:dev` uses `devUrl` (localhost:5173) for hot reload, but the API
still comes from the sidecar built in step 2 — re-run `pnpm sidecar` after
`dist/server` changes.

## Building installers locally

```bash
pnpm build                 # dist/server + dist/web
pnpm sidecar --target <rust-triple>
pnpm tauri:build           # installer lands in src-tauri/target/release/bundle/
```

Rust triples ↔ platform tags used by `scripts/build-sidecar.mjs`:
`x86_64-unknown-linux-gnu` (linux-x64), `aarch64-unknown-linux-gnu`
(linux-arm64), `x86_64-pc-windows-msvc` (win32-x64), `aarch64-pc-windows-msvc`
(win32-arm64), `x86_64-apple-darwin` (darwin-x64), `aarch64-apple-darwin`
(darwin-arm64).

> **After switching target platforms locally, delete `src-tauri/native/` by
> hand** — the sidecar build is copy-only/idempotent (it never deletes), so a
> stale prebuild from another platform would otherwise linger. CI always
> starts from a fresh checkout, so this is a local-only concern.

## Releases (GitHub Actions)

Push a tag — CI does everything else, on a tag-only trigger:

```bash
git tag v0.5.0
git push origin v0.5.0
```

`.github/workflows/release-desktop.yml` builds Linux + Windows + macOS in
parallel and uploads the installers to a **draft** GitHub Release. Cost notes
(calibrated to the free plan: 3,000 Actions min/month) are in the workflow
header: one 3-OS release ≈ 180–340 billable minutes (macOS bills 10×), and
release assets don't count against the 2 GB Packages quota.

## Signing status

Unsigned by default. The NSIS installer and Linux packages install fine; macOS
shows a Gatekeeper warning on first open. Signing/notarization options (Apple
Developer $99/yr, Azure Trusted Signing $9.99/mo) are documented in
`openpath-research/ci-desktop-release-draft.yml` (appendix) and can be added
to the workflow's `tauri-action` env block later.

## Verified so far (2026-10-13, Windows x64)

- Sidecar payload builds: `app.cjs` 3.5 MB + web 1.2 MB + better-sqlite3 2.0 MB
- Boot test: server binds a free port, `better-sqlite3` N-API prebuild loads,
  migrations run, DB created at `DATABASE_PATH`, demo data seeds on an empty DB
- `GET /` → 200 `text/html` (built SPA), `/learn` → 200 (SPA deep-link
  fallback), `/api/*` routes respond
- Installer sizes from the packaging research: deb ~115 MB, AppImage ~180 MB,
  dmg ~120–160 MB, NSIS ~115–150 MB
